# Technical Debt Register

> **Authority:** This document is the SSOT for known technical debt in `pipeline-orchestrator-for-codex`.  
> **Last reviewed:** 2026-05-11 after 5 adversarial review rounds (9 correction batches).  
> **Policy:** No debt listed here is a ship-blocker. All CRITICAL / HIGH / MEDIUM findings from adversarial review have been resolved. Debt is accepted because it is either (a) architectural and requires product-level decision, (b) documented limitation with honest user communication, or (c) cost of remediation exceeds risk in the current threat model.

## 1. Security Debt

### DEBT-SEC-001: TOCTOU in exec-window symlink rejection

```
Category: security
Severity: low
Identified in: Round 5
Status: accepted
Owner: runtime
```

**Location:** `src/security/exec-window-store.ts:34-41`

**Description:** `writeExecWindowAtomic()` checks `lstatSync(path).isSymbolicLink()` before writing, but there is a classic Time-Of-Check-Time-Of-Use (TOCTOU) race window: a symlink could be created between the `lstatSync` call and the subsequent `writeFileSync` / `renameSync`. Node.js does not provide an exclusive file-handle API that would eliminate this race on all platforms.

**Impact:** A local attacker with precise timing could potentially swap a legitimate exec-window file for a symlink between the check and the write. This requires local filesystem access and millisecond-precision timing.

**Rationale for acceptance:** The fix raises the bar significantly against the trivial static symlink attack (planting a symlink before the pipeline runs). Eliminating the race would require platform-specific file-handle APIs or kernel-level guarantees, which is out of scope for a Node.js plugin. The CJS hooks (`edit-guard-hook.cjs`) provide an additional layer of defense via `realpathSync`.

**Resolution trigger:** If the plugin is deployed in an environment where local attackers with filesystem access are in the threat model (e.g., multi-tenant CI runners without container isolation).

**Estimated remediation cost:** L (requires platform-specific file-handle code or native addon).

### DEBT-SEC-002: Prompt injection "non-invention rule" is prompt-only

```
Category: security
Severity: low
Identified in: Round 2
Status: accepted
Owner: runtime
```

**Location:** `src/security/prompt-injection-guard.ts`, `agents/core/pipeline-controller.md`

**Description:** The runtime has no mechanism to detect whether an agent "invented" evidence (e.g., fabricated test results, hallucinated file contents). The "non-invention rule" is enforced only via prompt instructions to the agents. There is no runtime validator that cross-checks agent claims against actual filesystem state.

**Impact:** In emulation mode (`strictAgents=false`), synthetic findings are generated by deterministic heuristics, so invention is structurally impossible. In real-agent mode (`strictAgents=true`), a misbehaving agent could theoretically invent evidence, and the controller has no way to detect it.

**Rationale for acceptance:** Adding runtime validation for every agent claim would require a full theorem-prover or sandboxed execution environment, which is architecturally incompatible with the current thin-delegator design. The skill's contract is that the *user* is the final gatekeeper for all gate decisions.

**Resolution trigger:** If the plugin moves to a fully autonomous mode where user gates are reduced or eliminated.

**Estimated remediation cost:** XL (requires sandboxed execution or formal verification layer).

## 2. Architecture Debt

### DEBT-ARCH-001: Fat Controller (1,883 lines)

```
Category: architecture
Severity: medium
Identified in: Round 2
Status: accepted
Owner: controller
```

**Location:** `src/controller/pipeline-controller.ts`

**Description:** The pipeline controller embeds classification logic, gating, proposal building, rollback routing, sentinel state management, session persistence, checkpoint validation, and closeout logic inline. It is a single file of ~1,883 lines that violates the Single Responsibility Principle.

**Impact:** Controller changes are high-risk because any modification can inadvertently affect phase transitions, gate logic, or persistence. Unit testing individual behaviors requires mocking large portions of the controller's internal state.

**Rationale for acceptance:** Extracting the controller into smaller modules would touch ~40% of the test suite and require extensive regression testing. The current controller is stable (100% test pass rate) and well-understood. Decomposition is a v1.0 concern, not a v0.4.x concern.

**Resolution trigger:** Before adding any new phase (e.g., "phase-4" or "pre-flight"), the controller MUST be decomposed. Target: < 600 lines per module.

**Estimated remediation cost:** XL (requires extracting `executeApprovedContinuation`, `SpecPhaseGateEvaluator`, `ResumeRouter`, and `ProposalBuilder` into standalone modules with their own test suites).

### DEBT-ARCH-002: Dispatcher is emulation harness, not real agent bridge

```
Category: architecture
Severity: medium
Identified in: Round 2
Status: accepted
Owner: dispatcher
```

**Location:** `src/dispatcher/single-agent-runner.ts`, `src/dispatcher/parallel-emulation-runner.ts`

**Description:** Diagnostic/test harness mode (`strictAgents=false`) uses local TypeScript heuristic functions instead of real `spawn_agent` calls. The "parallel emulation" runs `Promise.all` over `runSingleAgentRole`, which means all "agents" execute in the same Node process with zero context isolation. Operational dispatch for `/pipeline-orchestrator-for-codex:pipeline` now requires real agent support and blocks with `blocked-no-agent-runtime` when no adapter exists.

**Impact:** Review independence is violated by design in the default mode. The runtime cannot provide true adversarial review because the "reviewer" and "implementer" share the same heap, event loop, and memory.

**Rationale for acceptance:** The harness remains useful for deterministic tests and diagnostics, but it is no longer accepted as operational proof. Operational plugin use must surface a real-agent adapter or block honestly.

**Resolution trigger:** When Codex CLI exposes a stable programmatic `spawn_agent` test double, replace the remaining harness-only tests with real adapter tests.

**Estimated remediation cost:** L (requires shipping a working `agentRuntime` adapter and changing the default).

### DEBT-ARCH-003: Tests validate emulation shadows, not real agents

```
Category: architecture
Severity: medium
Identified in: Round 2
Status: accepted
Owner: runtime
```

**Description:** All 539 tests pass, but the vast majority validate the emulation path (local heuristic functions). There are no subprocess-based integration tests that verify real `spawn_agent` behavior, context isolation, or inter-process communication.

**Impact:** A regression in the real-agent dispatch path could go undetected for a long time. The `strictAgents=true` code path is exercised primarily by static analysis (TypeScript compilation) and a handful of BDD tests that read markdown files.

**Rationale for acceptance:** Real-agent testing requires a live Codex CLI environment with `multi_agent=true`, which is not available in the CI/test harness. The BDD tests (`tests/bdd/`) and the `codex-host-probe.ts` provide the best possible validation given the constraints.

**Resolution trigger:** When the plugin gains access to a stable `spawn_agent` test double or mock runtime in CI.

**Estimated remediation cost:** M (requires building a `spawn_agent` mock that exercises the dispatch protocol).

### DEBT-ARCH-004: Three colliding authorities

```
Category: architecture
Severity: medium
Identified in: Round 2
Status: accepted
Owner: docs / runtime
```

**Description:** Behavior authority is split across three (now four) sources:
1. `skills/pipeline/SKILL.md` — normative contract for Codex
2. `agents/core/pipeline-controller.md` — agent prompt
3. TypeScript runtime (`src/**/*.ts`) — executable code
4. `.kiro/specs/` — specification documents (new voice)

**Impact:** Drift between these sources can cause the runtime to behave differently from what the skill promises, or what the spec mandates.

**Rationale for acceptance:** The AGENTS.md establishes an explicit authority order (runtime > prompts > docs). The gap analysis admits this as a "mixed source-of-truth problem." Resolving it would require either (a) deleting the TS runtime and making markdown the SSOT (canonical's recommendation), or (b) generating prompts from the TS runtime automatically.

**Resolution trigger:** If a user reports behavior that contradicts the skill documentation.

**Estimated remediation cost:** XL (requires architectural decision: markdown-first vs runtime-first).

### DEBT-ARCH-005: Prompt registry validation theater

```
Category: architecture
Severity: low
Identified in: Round 2
Status: accepted
Owner: runtime
```

**Location:** `tests/unit/prompts/prompt-registry.test.ts`, `src/prompts/`

**Description:** 19 prompts are validated for required output blocks (e.g., `STATUS`, `FINDINGS`, `REVIEWERS`). However, the emulation path consumes **zero** prompts — the heuristic functions in `single-agent-runner.ts` return hardcoded JSON structures. The prompt validation ensures that *if* a real agent were spawned, it would receive a well-formed prompt, but it does not prove the prompt is effective.

**Impact:** The prompt registry could drift from the heuristic expectations without any test failing.

**Rationale for acceptance:** This is a natural consequence of DEBT-ARCH-002 (emulation mode). When real agents are used, the prompts are consumed. The validation provides value for the `strictAgents=true` path.

**Resolution trigger:** When the plugin moves to real-agent-by-default.

**Estimated remediation cost:** S (add integration tests that feed prompts to an LLM and parse the output).

### DEBT-ARCH-006: TS Compiler API coupling

```
Category: architecture
Severity: low
Identified in: Round 2
Status: accepted
Owner: controller
```

**Location:** `src/controller/pipeline-controller.ts` (scenario file resolution)

**Description:** `resolveApprovedScenarioFiles` uses `ts.createSourceFile` and `ts.resolveModuleName` to discover TypeScript scenario files. This couples the pipeline controller to the TypeScript compiler API, which is heavy and version-sensitive.

**Impact:** Upgrading TypeScript could break scenario file discovery. The controller cannot run in a pure JavaScript environment.

**Rationale for acceptance:** The function is used only for the spec-phase gate, which is a non-default path. Replacing it with a simple `glob` would lose type-aware module resolution.

**Resolution trigger:** TypeScript major version upgrade, or deployment to a non-TS environment.

**Estimated remediation cost:** M (replace with `glob` + manual module resolution).

### DEBT-ARCH-007: Canonical drift (75 TS files vs 0)

```
Category: architecture
Severity: medium
Identified in: Round 2
Status: accepted
Owner: runtime
```

**Description:** The canonical repository (`D:\Pipeline Orchestrator Claude`) has **zero** TypeScript files. Its entire runtime is expressed as markdown prompts, hooks, and Codex-native primitives. This repository has ~75 TS source files that implement the same behaviors in code.

**Impact:** Every bug fix or feature must be applied in two places (canonical markdown + TS runtime), or the two diverge.

**Rationale for acceptance:** The TS runtime was built deliberately as a test/contract harness that can run without Codex CLI. The canonical is the "production" target; this repo is the "portable harness." The AGENTS.md explicitly calls this an "intentional architectural difference."

**Resolution trigger:** Product decision to either (a) delete the TS runtime and align with canonical, or (b) maintain both as separate products with a parity test suite.

**Estimated remediation cost:** XL (requires deleting ~80% of the TS runtime or building a full parity test matrix).

### DEBT-ARCH-008: State Adapter partial migration

```
Category: architecture
Severity: low
Identified in: Round 2 / Round 3
Status: accepted
Owner: controller
```

**Location:** `src/controller/pipeline-controller.ts`, `src/controller/state-adapter.ts`

**Description:** The State Adapter is wired for gate-log and confidence persistence, but the controller still uses raw stores directly for session, checkpoint, and sentinel state. The public API accepts `stateAdapter` in `stores`, but `executeApprovedContinuation` and other internal paths reconstruct `stores` objects that may omit it.

**Impact:** Inconsistent abstraction layer. Some persistence goes through the adapter; some bypasses it.

**Rationale for acceptance:** Full migration would require touching every call site in the 1,883-line controller. The current state is functional and covered by tests. The adapter is now exposed in the public API, so external callers can use it consistently.

**Resolution trigger:** Before adding a new store type or migrating to a database-backed state layer.

**Estimated remediation cost:** M (requires auditing all `runtime.stores` references in the controller).

## 3. Harness Debt

### DEBT-HAR-001: Confidence scoring is a deterministic ledger, not AI-evaluated quality

```
Category: harness
Severity: low
Identified in: Round 2
Status: accepted
Owner: runtime
```

**Location:** `src/gates/confidence-model.ts`

**Description:** Confidence is purely arithmetic over hardcoded gate penalties (`-0.05`, `-0.1`, `-0.15` from `gate-registry.ts`). There is no external signal — no test coverage data, no build failure analysis, no LLM-evaluated risk assessment.

**Impact:** The confidence score accurately reflects "how many controller gates passed vs skipped," not "how good the code is." Presenting it as a quality metric would mislead users.

**Rationale for acceptance:** The score is structurally sound as a weighted gate ledger. It is documented as such in `confidence-model.ts` and `09-gap-analysis.md`.

**Resolution trigger:** If users request evidence-based confidence (e.g., "show me test coverage data").

**Estimated remediation cost:** L (requires integrating with test runners, linters, and static analysis tools).

### DEBT-HAR-002: Hooks and TS runtime are parallel universes

```
Category: harness
Severity: low
Identified in: Round 2
Status: accepted
Owner: hooks / runtime
```

**Description:** The CJS hooks (`hooks/*.cjs`) and the TypeScript runtime (`src/**/*.ts`) never call each other directly. They coordinate only via shared filesystem state (`sentinel-state.json`, `session-lock.json`, `protocol-events.jsonl`). If the TS runtime is used without Codex CLI hooks, the session-lock, dispatch-guard, and sentinel hooks do not fire.

**Impact:** The TS runtime lacks hook-level guards (e.g., `edit-guard`, `dispatch-guard`) when run outside Codex CLI. The runtime replicates some of these checks internally (e.g., `ensureWriteAuthorized`), but not all.

**Rationale for acceptance:** The hooks are designed for the Codex CLI event system (`SessionStart`, `UserPromptSubmit`, `PreToolUse`). The TS runtime is a programmatic API. Documenting the boundary is the correct mitigation.

**Resolution trigger:** If the TS runtime is used as the sole execution engine in production.

**Estimated remediation cost:** M (requires invoking hooks from the TS runtime via `execFileSync`).
