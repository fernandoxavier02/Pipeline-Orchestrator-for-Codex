# TRACE.md Schema — schema_version: 1

**Authoritative SSOT for the TRACE.md artifact emitted at the end of every pipeline run.**

This file replaces `designs/pipeline-orchestrator-v5-consolidated.md` §13 as the working spec; the design doc continues to describe the rationale and §13 is reduced to "see `references/trace-schema/v1.md`" going forward.

> **Status:** Wave 8-spec deliverable for v4.17.0. Stabilizes the contract used by `agents/core/pipeline-controller.md` Phase 3 closure (writer) and `scripts/validate-trace.cjs` (validator).

---

## 1. What is TRACE.md?

A single Markdown document, one per pipeline run, written to `.pipeline-orchestrator/runs/<run-id>/TRACE.md` in the user repo by default. It consolidates the audit trail produced during the run (gate decisions, confidence score, phase docs, artifacts touched, final verdict) into one PR-attachable file.

DoD criterion #2 (TRACE.md by default) and #3 (TRACE.md attachable to PR) reference this contract.

## 2. Output path

| Setting | Path | Versioned in user git? |
|---|---|---|
| Default | `.pipeline-orchestrator/runs/<run-id>/TRACE.md` (in repo root) | YES — user commits or `.gitignore`s |
| Opt-out (`pipeline-orchestrator.persist_runs: 'private'`) | `~/.claude/data/pipeline-orchestrator/runs/<run-id>/TRACE.md` | NO — outside repo |

The opt-out is set in `.claude/settings.json` (or `.claude/pipeline.local.md` frontmatter for project-scoped override).

## 3. `<run-id>` format

`{YYYYMMDD-HHMMSS}-{6char-random}-{slug}` — matches design §13 layout. The 6-char random suffix avoids collisions across worktrees and concurrent runs. The slug is derived from the user's request (lowercased, hyphenated, ≤32 chars).

Example: `20260506-172535-a3f7c1-wave8-spec-trace`.

## 4. Required fields (canonical order)

The writer MUST emit fields in the order listed below. The validator (`scripts/validate-trace.cjs`) enforces ordering.

### 4.1 Header block

```markdown
# Pipeline Run: {slug}

- trace_schema_version: 1
- timestamp_utc: {ISO 8601 UTC, e.g., 2026-05-06T17:25:35Z}
- started_at: {ISO 8601 UTC}
- ended_at: {ISO 8601 UTC}
- duration_seconds: {int}
- plugin_version: {semver, e.g., 4.17.0}
- user_identity: {git config user.email if in repo, else OS username}
- branch: {git branch or "(no-git)"}
- repo: {git remote URL or "(local)"}
- task: {original user request, ≤200 chars}
```

### 4.2 Classification section

```markdown
## Classification

- type: {Bug Fix | Feature | User Story | Audit | UX Simulation | Spec}
- type_source: {auto via /pipeline-orchestrator-for-codex:pipeline | manual via /pipeline-orchestrator-for-codex:<variant>}
- complexity: {SIMPLES | MEDIA | COMPLEXA}
- complexity_source: {auto (rationale: ...) | --simples flag | --media flag | --complexa flag | force_variant}
- justification: {2-3 sentences explaining the classification}
```

### 4.3 Pipeline Definition snapshot

```markdown
## Pipeline Definition (snapshot)

{Full copy of the pipeline shape that drove this run — the .md content (v5.0)
 or YAML config (v5.1+) loaded from references/pipelines/<variant>.md.}
```

### 4.4 Execution Log (one entry per phase)

```markdown
## Execution Log

### Phase: {phase_name}
- started_at: {ISO 8601 UTC}
- ended_at: {ISO 8601 UTC}
- agents: [{list of agent IDs invoked}]
- gate_before: {gate name or "(none)"} → {PASS | FAIL | SKIPPED}
- artifacts_produced: [{list of file paths}]
- status: {SUCCESS | FAILURE | SKIPPED}
- dispatch_mode: {parallel | serial}
- dispatch_decision_reason: {short prose — why this mode for this phase}
- emergent_invocations: [{list of {agent, motivo, evidência} or empty}]
```

`dispatch_mode` is per-phase, per Invariante #6 (`designs/pipeline-orchestrator-v5-consolidated.md` §9).

### 4.5 Final Verdict

```markdown
## Final Verdict

- status: {SUCCESS | DONE_WITH_CONCERNS | BLOCKED}
- artifacts: [{list of files modified or created}]
- open_issues: [{list of unresolved findings or empty}]
- recommended_next: {prose — what the user should do next}
```

### 4.6 Plan-mode override fields (Wave 8-spec)

Emitted only when `--no-plan` flag was passed. Always omitted otherwise.

```markdown
## Plan Mode

- plan_mode_skipped: {true | false}
- plan_override_attempted: {true | false}    # true if --no-plan was passed at all
- justification: {user-supplied reason for bypassing plan-architect, ≤500 chars}
```

When `complexity == COMPLEXA AND --no-plan was passed`:
- `plan_mode_skipped: false` (plan-architect ran anyway, override blocked per §8)
- `plan_override_attempted: true`
- `justification: <user input>` (preserved for audit even though override was rejected)

When `complexity == MEDIA AND --no-plan was passed`:
- `plan_mode_skipped: true`
- `plan_override_attempted: true`
- `justification: <user input>`

When `--no-plan` was NOT passed: the entire `## Plan Mode` section is omitted.

## 5. Validation (schema_version=1)

`scripts/validate-trace.cjs <path-to-TRACE.md>` exits:

| Exit | Meaning |
|---|---|
| 0 | TRACE.md conforms to schema_version=1 |
| 1 | TRACE.md fails schema check; stderr lists missing/malformed fields |

The validator MUST:
1. Confirm `trace_schema_version: 1` is present in the header block.
2. Confirm all required header fields are present and non-empty.
3. Confirm the four sections (Classification, Pipeline Definition, Execution Log, Final Verdict) appear in the canonical order.
4. Confirm at least one `### Phase:` entry exists in the Execution Log.
5. If `## Plan Mode` is present, confirm its three required fields.

## 6. Versioning and migration

`trace_schema_version: 1` is the v4.17.0 / v5.0 baseline. Future increments (`schema_version: 2+`) are additive — fields can be added at the end of each section, but existing field names and ordering are frozen for the lifetime of the major version.

When a TRACE.md is generated against a schema the validator does not understand, the validator exits 1 with a clear "unsupported schema version" message.

## 7. Retention

TRACEs are small (typically <50 KB). Retention policy is **user-controlled** — they ship in git by default, and users decide whether to commit, `.gitignore`, or periodically clean up. The plugin does not implement automatic rotation.
